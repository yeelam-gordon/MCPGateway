# Shared MCP Gateway

[English](../../README.md)

## RAM を節約。作業のためにコンテキストを確保。ツールは必要なときだけ。

**エージェントを増やすなら、同じ MCP 設定のコピーではなく、成果を増やすべきです。**

### 5 エージェント、12 MCP 接続、共有設定は 1 つ

*例：**12** 接続で **1,000** ツールを提供し、独立した設定 1 つにつきローカルプロセスの RAM を **1.5 GB** 使用する場合。*

| 利点 | エージェントごとの個別設定 | MCPGateway を使用 |
|---|---|---|
| **RAM を節約** | 5 つの個別設定で合計 **7.5 GB**。 | **1.5 GB を共有**し、別途ゲートウェイ/コネクターのオーバーヘッドが発生。**6 GB の重複 RAM を回避**。 |
| **作業のためにコンテキストを確保。ツールは必要なときだけ。** | 各エージェントが **1,000 個のツール定義**を事前に読み込み、MCP 接続を追加するとさらに増える可能性があります。 | 事前に読み込むのは **6 個のゲートウェイツールだけで、定義数は 99.4% 減少**。**1,000** ツールはすべて利用でき、各エージェントは必要なものだけを検出して読み込みます。接続を追加しても、全エージェントが完全なカタログを事前読み込みする必要はありません。 |

**エージェントと MCP 接続はそのまま。各セッションに同じコピーを持たせるのはやめましょう。**

*RAM の数値は説明用で、実測された節約量ではありません。エージェント自身のメモリは別途必要です。定義数の削減はトークン削減を意味せず、既に遅延読み込みを行うクライアントではコンテキスト上の利点が小さい場合があります。共有によってモデルのコンテキストウィンドウが拡大したり、総 RAM 使用量が一定になったりすることはありません。*

## 仕組み

ゲートウェイがエージェントへ公開するツールは常に 6 個です。4 個は機能の検索と呼び出し、2 個は排他的なワークフローが必要な連携に使います。接続を追加しても初期インターフェイスは増えず、完全なスキーマは選択したツールについてのみ読み込まれます。既に設定・認証済みの接続を再利用し、サービスのインストールや資格情報の提供は行いません。

1 つの共有 MCP カタログを複数のエージェントで利用でき、Copilot の **10** 接続から始め、**2** 個の新しい接続を含む対応済みの Claude 設定を明示的に移行すると、両方のエージェントが同じ **12** 接続を利用できますが、プラグインをインストールしただけでは自動的に統合されません。同名の項目はエイリアス定義が完全に同一の場合だけ重複排除され、同じサービスを指すだけでは不十分で、競合時はレビューのため停止します。移行はプレビューとバックアップを先に行い、未対応のネイティブ設定を拒否しますが、すべてのネイティブクライアントでエンドツーエンドテスト済みという意味ではないため、[移行ガイド（英語）](../CLIENTS.md#cross-client-migration)を参照してください。

**前提条件：** Node.js 24 以降、npm、Git、および現在の初期設定に必要なプラグイン対応 Copilot CLI。Agency は任意です。

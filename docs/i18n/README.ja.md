[English](../../README.md)

## 既存の MCP バックエンドを 1 つのゲートウェイで共有

Shared MCP Gateway を使うと、Copilot が最初に読み込むのは固定の **6 個のゲートウェイツール**だけです。その後、設定済みバックエンドのツールを必要に応じて検索して呼び出します。バックエンドカタログに約 **1,000 個のツール**があっても、すべての定義を最初からクライアントへ渡す必要はありません。

複数の Copilot CLI セッションでバックエンドカタログと接続を再利用し、ローカルサーバーの重複起動を減らします。ゲートウェイが MCP サーバーをインストールしたり、資格情報を提供したりすることはありません。サーバー設定と認証には、これまでの方法を引き続き使用してください。

6 個のツールは、探索/実行用の 4 個と、汎用的なサーバーリース用の 2 個です。リースは排他的なワークフロー状態を必要とする任意のバックエンドに使え、ブラウザー自動化専用ではありません。

## 前提条件

- Node.js 24 以降、npm、Git
- プラグインをサポートする Copilot CLI
- 既存の Copilot MCP 設定と、バックエンドが必要とする認証
- Agency は任意です。通常の Copilot CLI 利用には不要です

## インストール

次のコマンドは Copilot チャット内ではなく、**ターミナル**で実行します。

```text
copilot plugin marketplace add yeelam-gordon/MCPGateway
copilot plugin install shared-mcp-gateway@mcp-gateway
```

次に Copilot を起動し、Copilot 内で実行します。

```text
/mcp-gateway-setup
```

プラグインをインストールしただけでは MCP 設定は移行されません。セットアップは最初にプレビューを表示し、承認後に既存設定をバックアップして、バックエンド定義を非公開ディレクトリへ保存し、クライアント設定を共有ゲートウェイコネクターへ切り替えます。

出力されたバックアップパスと正確な復元コマンドを保管してください。バックエンドカタログとバックアップには資格情報が含まれる場合があるため、公開したりバージョン管理へコミットしたりしないでください。

完了後、Copilot を閉じて開き直します。コネクターの初回利用時にゲートウェイが自動起動するため、別のターミナルで常時実行する必要はありません。

## 仕組み

1. `list_servers` は、すべてのバックエンドを起動せずに設定済みエイリアスを一覧表示します。
2. `search_tools` は、指定したバックエンドから関連するツールの概要を検索します。
3. `get_tool_schema` は、選択した 1 ツールの完全な入力スキーマだけを取得します。
4. `call_tool` は、引数と許可リストを検証してツールを呼び出します。
5. `claim_server` と `release_server` は、排他的アクセスが必要なサーバーのワークフロー全体を保護し、実行中の呼び出しが終了してからリースを解放します。

MCP クライアント、ゲートウェイ、MCP サーバーはそれぞれ異なる役割を持ちますが、通常の利用でプロトコルの詳細を理解する必要はありません。既存のバックエンドを設定し、Copilot からゲートウェイ経由で探索・実行するだけです。

## 更新と復元

プラグインを更新した後、新しいランタイムを明示的に採用するには `/mcp-gateway-setup` を実行します。実行中の呼び出しが終わってから更新を適用し、Copilot を開き直してください。プラグインのダウンロードだけでは、稼働中のゲートウェイは置き換わりません。

セットアップに失敗した場合は Copilot を閉じ、出力された正確なバックアップパスと復元コマンドを使用してください。非公開のバックエンドディレクトリを削除して復旧しようとしないでください。
設定同期、クライアント統合、リース、トラブルシューティングの詳細は、英語版 [README](../../README.md) を参照してください。

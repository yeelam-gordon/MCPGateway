# Shared MCP Gateway त्वरित शुरुआत

[English](../../README.md)

> यह स्थानीयकृत त्वरित शुरुआत है। उन्नत उपयोग और नवीनतम तकनीकी विवरणों के लिए अंग्रेज़ी [README](../../README.md) आधिकारिक स्रोत है।

## मौजूदा MCP बैकएंड के लिए एक गेटवे

Shared MCP Gateway की मदद से Copilot शुरुआत में केवल **6 गेटवे टूल** वाला स्थिर इंटरफ़ेस लोड करता है। इसके बाद वह आपके पहले से कॉन्फ़िगर किए गए बैकएंड के टूल को ज़रूरत पर खोजता और कॉल करता है। कैटलॉग में लगभग **1,000 टूल** होने पर भी सभी परिभाषाएँ पहले से क्लाइंट को देने की आवश्यकता नहीं होती।

बैकएंड कैटलॉग और कनेक्शन कई Copilot CLI सत्रों के बीच दोबारा उपयोग होते हैं, जिससे स्थानीय सर्वर बार-बार शुरू करने की ज़रूरत कम होती है। गेटवे MCP सर्वर इंस्टॉल नहीं करता और क्रेडेंशियल उपलब्ध नहीं कराता; सर्वर और प्रमाणीकरण को अपने मौजूदा तरीके से कॉन्फ़िगर करते रहें।

6 टूल में खोज/निष्पादन के 4 टूल और सामान्य सर्वर लीज़ के 2 टूल शामिल हैं। लीज़ ऐसे किसी भी बैकएंड के लिए है जिसे विशेष वर्कफ़्लो स्थिति चाहिए; यह केवल ब्राउज़र ऑटोमेशन के लिए नहीं है।

## आवश्यकताएँ

- Node.js 24 या नया संस्करण, npm और Git
- प्लगइन समर्थन वाला Copilot CLI
- मौजूदा Copilot MCP कॉन्फ़िगरेशन और बैकएंड के लिए आवश्यक प्रमाणीकरण
- Agency वैकल्पिक है; सामान्य Copilot CLI उपयोग के लिए इसकी आवश्यकता नहीं है

## इंस्टॉलेशन

इन कमांड को Copilot चैट में नहीं, **टर्मिनल** में चलाएँ:

```text
copilot plugin marketplace add yeelam-gordon/MCPGateway
copilot plugin install shared-mcp-gateway@mcp-gateway
```

इसके बाद Copilot शुरू करें और Copilot के अंदर चलाएँ:

```text
/mcp-gateway-setup
```

केवल प्लगइन इंस्टॉल करने से MCP कॉन्फ़िगरेशन माइग्रेट नहीं होता। सेटअप पहले पूर्वावलोकन दिखाता है; स्वीकृति के बाद यह मौजूदा कॉन्फ़िगरेशन का बैकअप बनाता है, बैकएंड परिभाषाओं को निजी डायरेक्टरी में रखता है और क्लाइंट कॉन्फ़िगरेशन को साझा गेटवे कनेक्टर पर बदलता है।

दिखाए गए बैकअप पथ और सटीक पुनर्स्थापना कमांड को सुरक्षित रखें। बैकएंड कैटलॉग और बैकअप में क्रेडेंशियल हो सकते हैं; उन्हें प्रकाशित या वर्शन कंट्रोल में कमिट न करें।

पूरा होने पर Copilot बंद करके दोबारा खोलें। कनेक्टर के पहले उपयोग पर गेटवे अपने आप शुरू होता है; अलग टर्मिनल चालू रखने की आवश्यकता नहीं है।

## यह कैसे काम करता है

1. `list_servers` सभी बैकएंड शुरू किए बिना कॉन्फ़िगर किए गए उपनाम दिखाता है।
2. `search_tools` किसी चुने हुए बैकएंड में संबंधित टूल सारांश खोजता है।
3. `get_tool_schema` केवल चुने गए टूल का पूरा इनपुट स्कीमा प्राप्त करता है।
4. `call_tool` टूल कॉल करने से पहले आर्ग्युमेंट और अनुमति सूची की जाँच करता है।
5. `claim_server` और `release_server` विशेष पहुँच वाले सर्वर के पूरे वर्कफ़्लो की रक्षा करते हैं और सक्रिय कॉल पूरे होने के बाद लीज़ छोड़ते हैं।

MCP क्लाइंट, गेटवे और MCP सर्वर की भूमिकाएँ अलग हैं, लेकिन रोज़मर्रा के उपयोग में प्रोटोकॉल का विवरण जानना आवश्यक नहीं है: बैकएंड पहले की तरह कॉन्फ़िगर करें और Copilot को गेटवे के माध्यम से उन्हें खोजने और कॉल करने दें।

## अपडेट और पुनर्स्थापना

प्लगइन अपडेट करने के बाद नया रनटाइम स्पष्ट रूप से अपनाने के लिए `/mcp-gateway-setup` चलाएँ। सक्रिय कॉल पूरे होने दें, फिर अपडेट लागू करके Copilot दोबारा खोलें; केवल प्लगइन डाउनलोड करने से चल रहा गेटवे नहीं बदलता।

सेटअप विफल हो तो Copilot बंद करें और आउटपुट में दिखाए गए सटीक बैकअप पथ तथा पुनर्स्थापना कमांड का उपयोग करें। सुधार के लिए निजी बैकएंड डायरेक्टरी को न हटाएँ।
कॉन्फ़िगरेशन सिंक, क्लाइंट एकीकरण, लीज़ और समस्या निवारण के लिए अंग्रेज़ी [README](../../README.md) देखें।

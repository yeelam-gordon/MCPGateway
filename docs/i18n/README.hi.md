# Shared MCP Gateway

[English](../../README.md)

> यह स्थानीयकृत अवलोकन है। संपूर्ण इंस्टॉलेशन, अपग्रेड और तकनीकी विवरणों के लिए अंग्रेज़ी [README](../../README.md) और नीचे लिंक की गई अंग्रेज़ी क्लाइंट गाइड आधिकारिक स्रोत हैं।

## RAM बचाएँ। अपने काम के लिए कॉन्टेक्स्ट रखें। टूल ज़रूरत पर।

**ज़्यादा एजेंट का अर्थ ज़्यादा काम पूरा होना चाहिए, एक ही MCP कॉन्फ़िगरेशन की ज़्यादा प्रतियाँ नहीं।**

### 5 एजेंट। 12 MCP कनेक्शन। एक साझा कॉन्फ़िगरेशन।

*उदाहरण: ये **12** कनेक्शन **1,000** टूल उपलब्ध कराते हैं और हर स्वतंत्र सेटअप **1.5 GB** स्थानीय प्रोसेस RAM उपयोग करता है।*

| लाभ | हर एजेंट के लिए अलग सेटअप | MCPGateway के साथ |
|---|---|---|
| **RAM बचाएँ** | पाँच स्वतंत्र MCP सेटअप में **7.5 GB**। | **1.5 GB साझा**, साथ में गेटवे/कनेक्टर ओवरहेड। **6 GB दोहराई गई मेमोरी बचती है।** |
| **काम के लिए कॉन्टेक्स्ट। टूल ज़रूरत पर।** | हर एजेंट पहले से **1,000 टूल परिभाषाएँ** लोड करता है; MCP कनेक्शन जोड़ने पर संख्या बढ़ सकती है। | पहले से केवल **6 गेटवे टूल—99.4% कम परिभाषाएँ**। सभी **1,000** टूल उपलब्ध रहते हैं; हर एजेंट केवल आवश्यक टूल खोजता और लोड करता है। नए कनेक्शन जोड़ने पर हर एजेंट में पूरा कैटलॉग लोड नहीं करना पड़ता। |

**अपने एजेंट और MCP कनेक्शन रखें। हर सत्र को अपनी अलग प्रति ढोने से रोकें।**

*RAM के आँकड़े केवल उदाहरण हैं, मापी गई बचत नहीं; एजेंट की अपनी मेमोरी अतिरिक्त है। परिभाषाओं की संख्या टोकन बचत नहीं है, और पहले से विलंबित लोडिंग करने वाले क्लाइंट को कम कॉन्टेक्स्ट लाभ मिल सकता है। साझा करने से मॉडल की कॉन्टेक्स्ट विंडो बड़ी या कुल RAM स्थिर नहीं होती।*

## यह कैसे काम करता है

गेटवे एजेंट को हमेशा 6 टूल दिखाता है: क्षमताएँ खोजने और कॉल करने के लिए 4, तथा विशेष वर्कफ़्लो वाली इंटीग्रेशन के लिए 2। कनेक्शन जोड़ने से शुरुआती इंटरफ़ेस नहीं बढ़ता; पूरा स्कीमा केवल चुने गए टूल के लिए लोड होता है। आपके पहले से कॉन्फ़िगर और प्रमाणित कनेक्शन दोबारा उपयोग होते हैं; सेवाएँ इंस्टॉल या क्रेडेंशियल उपलब्ध नहीं कराए जाते।

**आवश्यकताएँ:** Node.js 24 या नया, npm, Git और मौजूदा आरंभिक प्रक्रिया के लिए प्लगइन समर्थन वाला Copilot CLI। Agency वैकल्पिक है।

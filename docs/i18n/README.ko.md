# Shared MCP Gateway 빠른 시작

[English](../../README.md)

> 이 문서는 현지화된 빠른 시작 안내입니다. 고급 사용법과 최신 기술 세부 정보는 영어 [README](../../README.md)가 기준입니다.

## 하나의 게이트웨이로 기존 MCP 백엔드 공유

Shared MCP Gateway를 사용하면 Copilot은 처음에 고정된 **6개의 게이트웨이 도구**만 불러오고, 이미 구성한 백엔드의 도구를 필요할 때 검색하고 호출합니다. 백엔드 카탈로그에 약 **1,000개의 도구**가 있어도 모든 정의를 처음부터 클라이언트에 노출할 필요가 없습니다.

여러 Copilot CLI 세션이 백엔드 카탈로그와 연결을 재사용하므로 로컬 서버가 중복으로 시작되는 일을 줄일 수 있습니다. 게이트웨이는 MCP 서버를 대신 설치하거나 자격 증명을 제공하지 않습니다. 기존 방식으로 서버와 인증을 계속 구성하세요.

6개 도구는 검색/실행용 4개와 범용 서버 임대용 2개로 구성됩니다. 임대는 독점 워크플로 상태가 필요한 모든 백엔드에 사용할 수 있으며 브라우저 자동화 전용이 아닙니다.

## 사전 요구 사항

- Node.js 24 이상, npm, Git
- 플러그인을 지원하는 Copilot CLI
- 기존 Copilot MCP 구성과 백엔드에 필요한 인증
- Agency는 선택 사항이며 일반 Copilot CLI 사용자에게는 필요하지 않습니다

## 설치

다음 명령은 Copilot 대화가 아니라 **터미널**에서 실행하세요.

```text
copilot plugin marketplace add yeelam-gordon/MCPGateway
copilot plugin install shared-mcp-gateway@mcp-gateway
```

그런 다음 Copilot을 시작하고 Copilot 안에서 실행하세요.

```text
/mcp-gateway-setup
```

플러그인 설치만으로는 MCP 구성이 마이그레이션되지 않습니다. 설정 명령은 먼저 미리 보기를 보여 줍니다. 승인하면 기존 구성을 백업하고, 백엔드 정의를 비공개 디렉터리에 저장한 뒤, 클라이언트 구성을 공유 게이트웨이 커넥터로 전환합니다.

출력된 백업 경로와 정확한 복원 명령을 보관하세요. 백엔드 카탈로그와 백업에는 자격 증명이 포함될 수 있으므로 공개하거나 버전 관리에 커밋하지 마세요.

완료 후 Copilot을 닫았다가 다시 여세요. 커넥터를 처음 사용할 때 게이트웨이가 자동으로 시작되므로 별도 터미널에서 계속 실행할 필요가 없습니다.

## 작동 방식

1. `list_servers`는 모든 백엔드를 시작하지 않고 구성된 별칭을 나열합니다.
2. `search_tools`는 지정한 백엔드에서 관련 도구 요약을 검색합니다.
3. `get_tool_schema`는 선택한 도구 하나의 전체 입력 스키마만 가져옵니다.
4. `call_tool`은 인수와 허용 목록을 검증한 뒤 도구를 호출합니다.
5. `claim_server`와 `release_server`는 독점 접근이 필요한 서버의 전체 워크플로를 보호하고 활성 호출이 끝난 뒤 임대를 해제합니다.

MCP 클라이언트, 게이트웨이, MCP 서버는 서로 다른 역할을 하지만 일상적인 사용에 프로토콜 세부 지식은 필요하지 않습니다. 기존 백엔드를 구성하고 Copilot이 게이트웨이를 통해 검색하고 호출하도록 하면 됩니다.

## 업데이트 및 복원

플러그인을 업데이트한 뒤 `/mcp-gateway-setup`을 실행해야 새 런타임을 명시적으로 적용할 수 있습니다. 활성 호출이 끝난 다음 업데이트를 적용하고 Copilot을 다시 여세요. 플러그인 다운로드만으로는 실행 중인 게이트웨이가 교체되지 않습니다.

설정에 실패하면 Copilot을 닫고 출력된 정확한 백업 경로와 복원 명령을 사용하세요. 비공개 백엔드 디렉터리를 삭제하는 방식으로 문제를 해결하지 마세요.
구성 동기화, 클라이언트 통합, 임대, 문제 해결에 대한 자세한 내용은 영어 [README](../../README.md)를 참고하세요.

## RAM을 절약하고 작업을 위한 컨텍스트를 확보하세요. 도구는 필요할 때만.

**에이전트가 늘어나면 같은 MCP 설정 사본이 아니라 더 많은 결과가 나와야 합니다.**

### 에이전트 5개, MCP 연결 12개, 공유 설정 1개

*예시: **12**개 연결이 **1,000**개 도구를 제공하고, 독립 설정 하나가 로컬 프로세스 RAM **1.5 GB**를 사용하는 경우입니다.*

| 이점 | 에이전트별 독립 설정 | MCPGateway 사용 |
|---|---|---|
| **RAM 절약** | 독립 설정 5개에 총 **7.5 GB**. | **1.5 GB 공유**, 게이트웨이/커넥터 오버헤드 별도. **중복 RAM 6 GB 절약.** |
| **작업을 위한 컨텍스트 확보, 도구는 필요할 때만** | 에이전트마다 **1,000개 도구 정의**를 미리 불러오며 MCP 연결을 추가하면 더 늘어날 수 있습니다. | 처음에는 **게이트웨이 도구 6개만, 정의 수 99.4% 감소**. **1,000**개 도구는 모두 사용할 수 있고 각 에이전트는 필요한 도구만 찾아 불러옵니다. 연결을 추가해도 모든 에이전트가 전체 카탈로그를 미리 로드할 필요가 없습니다. |

**에이전트와 MCP 연결은 유지하고, 모든 세션이 같은 사본을 들고 다니게 하지는 마세요.**

*RAM 수치는 설명을 위한 예시이며 측정된 절감량이 아닙니다. 에이전트 자체 메모리는 별도입니다. 정의 수 감소는 토큰 절감을 뜻하지 않으며 이미 지연 로딩을 사용하는 클라이언트는 컨텍스트 이점이 더 작을 수 있습니다. 공유한다고 모델의 컨텍스트 창이 커지거나 전체 RAM 사용량이 일정해지는 것은 아닙니다.*

## 작동 방식

게이트웨이는 에이전트에 항상 6개 도구를 제공합니다. 4개는 기능 검색과 호출에, 2개는 독점 워크플로가 필요한 통합에 사용됩니다. 연결을 추가해도 초기 인터페이스는 커지지 않으며 전체 스키마는 선택한 도구에 대해서만 로드됩니다. 이미 구성하고 인증한 연결을 재사용하며 서비스 설치나 자격 증명 제공은 하지 않습니다.

하나의 공유 MCP 카탈로그를 여러 에이전트가 사용할 수 있으며, Copilot의 연결 **10**개에서 시작해 새 연결 **2**개가 포함된 지원 Claude 구성을 명시적으로 마이그레이션하면 두 에이전트 모두 같은 연결 **12**개를 사용할 수 있지만, 플러그인 설치만으로 자동 병합되지는 않습니다. 이름이 같은 항목은 별칭 정의가 완전히 동일할 때만 중복 제거되며 같은 서비스를 가리킨다는 이유만으로는 충분하지 않고, 충돌이 있으면 검토를 위해 중지됩니다. 마이그레이션은 미리 보기와 백업을 먼저 수행하고 지원하지 않는 네이티브 설정을 거부하며 모든 네이티브 클라이언트가 엔드투엔드로 테스트되었다는 의미는 아니므로, [마이그레이션 가이드(영문)](../CLIENTS.md#cross-client-migration)를 참조하세요.

**사전 요구 사항:** Node.js 24 이상, npm, Git, 현재 부트스트랩에 필요한 플러그인 지원 Copilot CLI. Agency는 선택 사항입니다.

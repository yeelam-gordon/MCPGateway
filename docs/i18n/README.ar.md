# MCPGateway — مشاركة خوادم MCP المحلية بين جلسات وكلاء البرمجة

[English](../../README.md)

> هذه نظرة عامة مترجمة. يظل ملف [README](../../README.md) الإنجليزي ودليل العملاء الإنجليزي المرتبط أدناه المرجعين المعتمدين للتثبيت الكامل والترقية والتفاصيل التقنية.

لا تحتاج كل جلسة Copilot CLI إلى تشغيل نسخة أخرى من خادم MCP نفسه. شارك الخدمات الخلفية المحلية المهيأة، واكتشف الأدوات عند الحاجة، ونسّق مسارات العمل الحصرية. هذه ليست منصة حوكمة API للمؤسسات.

**المتطلبات:** Node.js 24 أو أحدث، وnpm، وGit، وCopilot CLI مع الإضافات، وخدمات MCP مهيأة ومصادق عليها مسبقًا. يمر التثبيت الأول حاليًا عبر Copilot CLI؛ Windows منصة الاختبار الرئيسية وAgency اختياري. تختلف مستويات التوافق والتحقق بين العملاء.

تعرض البوابة دائمًا 6 أدوات للوكيل: 4 لاكتشاف القدرات واستدعائها، و2 لعمليات التكامل التي تحتاج إلى سير عمل حصري. لا تؤدي إضافة الاتصالات إلى تكبير الواجهة الأولية؛ ولا يُحمّل المخطط الكامل إلا للأداة المختارة. تُعاد الاستفادة من الاتصالات التي أعددتها وصادقت عليها، من دون تثبيت خدمات أو توفير بيانات اعتماد.

مثلًا، يمكن إضافة اتصالين جديدين بترحيل صريح من إعداد Claude مدعوم إلى **10** اتصالات في Copilot، ليستخدم الوكيلان الاتصالات الـ **12** نفسها.

- تثبيت الإضافة وحده لا يدمج الإعدادات. لا تُزال ازدواجية الإدخالات المتساوية في الاسم إلا إذا تطابقت تعريفات أسمائها المستعارة؛ الإشارة إلى الخدمة نفسها لا تكفي. تتوقف العملية عند وجود تعارض لإتاحة المراجعة.
- يعرض الترحيل معاينة أولًا، وينشئ نسخة احتياطية ويرفض الإعدادات الخاصة بالعميل التي لا يدعمها الترحيل.
- لا يعني ذلك اختبار التكامل المباشر مع جميع العملاء من البداية إلى النهاية. [دليل الترحيل (بالإنجليزية)](../CLIENTS.md#cross-client-migration).

## الإعداد والاستدعاء الأول

```powershell
copilot plugin marketplace add yeelam-gordon/MCPGateway
copilot plugin install shared-mcp-gateway@mcp-gateway
```

1. بعد التثبيت افتح Copilot CLI واستدعِ `/mcp-gateway-setup`. راجع المعاينة قبل الموافقة على التغييرات المطلوبة فقط. أغلق Copilot ثم أعد فتحه ونفّذ `readinessCommand` الدقيق الذي أعاده الإعداد. احتفظ بالنسخ الاحتياطية الخاصة وأوامر التراجع.
2. استدعِ `list_servers` مع `{}`: يُفترض ظهور الأسماء المستعارة والحالات ومؤشرات الوصول الحصري للخدمات المهيأة. اختر خدمة خلفية مأذونًا بها، وابحث عن مصطلح يناسب المهمة باستخدام `search_tools`، ثم اطلب مخطط إدخال الأداة عبر `get_tool_schema`. جهّز الوسائط وفق المخطط واستخدم `call_tool` لتنفيذ قراءة معتمدة. النتيجة المتوقعة سجل فعلي أو نتيجة فارغة موضحة؛ افحص الأخطاء أيضًا، فمجرد وصول رد لا يثبت النجاح.
3. إذا كان `requiresExclusiveAccess: true`، استخدم `claim_server` قبل البحث و`release_server` بعد انتهاء جميع الاستدعاءات. لا تحتاج الخدمات غير الحصرية إلى حجز. لا تعاود المحاولة عند انتهاء المهلة مع نتيجة مجهولة؛ راجع العمل الجاري ونسّق إعادة التشغيل. إذا كانت النتيجة مجهولة، تبقى الخدمة الخلفية ذات الوصول الحصري محظورة حتى إعادة تشغيل البوابة؛ تحرير الحجز أو فصل العميل لا يرفع الحظر بأمان، وفصل الاتصال لا يلغي العملية.

## الحدود والخصوصية والاستعادة

العثور على هذا المستودع عبر Claude Code أو Codex أو Gemini CLI أو Kimi أو Qwen CLI لا يضمن التكامل المباشر مع العميل. لا يوجد مسار تثبيت موثق لـ Gemini CLI هنا؛ Antigravity عميل آخر. اختُبر Kimi على مستوى المهايئ فقط. قد تحتوي الإعدادات والنسخ الاحتياطية على بيانات اعتماد؛ لا تنشرها ولا تضفها إلى التحكم في الإصدارات. قد تتصل الخدمات الخلفية بخدمات بعيدة؛ المشاركة لا تعني العمل دون اتصال ولا تضمن توفيرًا ثابتًا في RAM أو رموز النموذج (tokens).

إذا كانت القائمة فارغة، تحقق من الإعداد المحدد ومعاينة الترحيل. إن لم تجد أدوات، استخدم كلمات من وصف الخدمة الخلفية. عند فشل المصادقة أو الجاهزية اتبع المرجع التشغيلي، ولا تبدأ عملية موازية لتجاوز البوابة. استعادة إعداد العميل لا توقف بيئة التشغيل المستمرة؛ عند التوقف عن الاستخدام راجع تسليم الطلب للمشغّل وفحوص الإتمام.

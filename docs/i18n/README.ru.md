# Краткое руководство по Shared MCP Gateway

[English](../../README.md)

> Это локализованное краткое руководство. Английский [README](../../README.md) является основным источником сведений о расширенном использовании и актуальных технических деталях.

## Один шлюз для существующих MCP-бэкендов

Shared MCP Gateway позволяет Copilot сначала загрузить фиксированный интерфейс из **6 инструментов шлюза**, а затем по мере необходимости находить и вызывать инструменты уже настроенных бэкендов. Даже если в каталоге около **1 000 инструментов**, клиенту не требуется получать все определения заранее.

Каталог и подключения к бэкендам повторно используются несколькими сеансами Copilot CLI, что сокращает число дублирующихся запусков локальных серверов. Шлюз не устанавливает MCP-серверы и не предоставляет учетные данные: продолжайте настраивать серверы и аутентификацию привычным способом.

Шесть инструментов включают 4 средства обнаружения/выполнения и 2 универсальных средства аренды сервера. Аренда подходит для любого бэкенда, которому требуется эксклюзивное состояние рабочего процесса, и не ограничена автоматизацией браузера.

## Требования

- Node.js 24 или новее, npm и Git
- Copilot CLI с поддержкой плагинов
- Существующая конфигурация MCP для Copilot и аутентификация, необходимая бэкендам
- Agency необязателен и не нужен для обычной работы с Copilot CLI

## Установка

Выполните эти команды в **терминале**, а не в чате Copilot:

```text
copilot plugin marketplace add yeelam-gordon/MCPGateway
copilot plugin install shared-mcp-gateway@mcp-gateway
```

Затем запустите Copilot и выполните внутри Copilot:

```text
/mcp-gateway-setup
```

Сама установка плагина не переносит конфигурацию MCP. Сначала программа настройки показывает предварительный просмотр; после подтверждения она создает резервную копию, сохраняет определения бэкендов в закрытом каталоге и переключает конфигурацию клиента на коннектор общего шлюза.

Сохраните показанные путь к резервной копии и точную команду восстановления. Каталог бэкендов и резервные копии могут содержать учетные данные; не публикуйте их и не добавляйте в систему контроля версий.

После завершения закройте и снова откройте Copilot. Шлюз запускается автоматически при первом использовании коннектора; держать отдельный терминал открытым не требуется.

## Как это работает

1. `list_servers` перечисляет настроенные псевдонимы, не запуская все бэкенды.
2. `search_tools` ищет описания подходящих инструментов в указанном бэкенде.
3. `get_tool_schema` получает только полную входную схему выбранного инструмента.
4. `call_tool` проверяет аргументы и список разрешений перед вызовом инструмента.
5. `claim_server` и `release_server` защищают весь рабочий процесс сервера, которому нужен эксклюзивный доступ, и освобождают аренду после завершения активных вызовов.

Клиент MCP, шлюз и сервер MCP выполняют разные роли, но для повседневной работы знать детали протокола не требуется: настройте бэкенды как обычно, а Copilot найдет и вызовет их через шлюз.

## Обновление и восстановление

После обновления плагина выполните `/mcp-gateway-setup`, чтобы явно перейти на новую среду выполнения. Дождитесь завершения активных вызовов, примените обновление и снова откройте Copilot; загрузка плагина сама по себе не заменяет уже работающий шлюз.

Если настройка завершилась с ошибкой, закройте Copilot и используйте показанные точный путь к резервной копии и команду восстановления. Не удаляйте закрытый каталог бэкендов в попытке восстановить систему.
Сведения о синхронизации конфигурации, интеграции клиентов, аренде и устранении неполадок см. в английском [README](../../README.md).

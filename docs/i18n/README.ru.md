Несколько сессий используют один набор бэкендов: меньше дублирования памяти и повторных запусков. Проверенный путь SDK/stdio сохраняет текущее MCP-соединение при добавлении конфигурации (существующее соединение вашего агента со шлюзом).

Концептуальная иллюстрация с английскими подписями, не снимок программы и не тест производительности. [SVG](../../assets/mcp-gateway-benefits.svg)

- **Не дублируйте память бэкендов:** При условном общем использовании 5 × 1.5 GB устраняется 6 GB дублирования **до** накладных расходов шлюза и коннекторов. Это не измеренная чистая экономия.
- **Избегайте повторного запуска бэкендов:** Если все пять сессий используют двенадцать stdio-сервисов, число запусков меняется с 60 → 12. Это не ускорение запуска на 80%.
- **Сохраняйте текущее MCP-соединение:** В опыте SDK/stdio соединение сохранилось после добавления только конфигурации и перезапуска собственного шлюза по завершении работы. Это не горячая перезагрузка, не продолжение активных вызовов и не проверка всех нативных интерфейсов диалога. Первичная регистрация и обновления среды могут требовать перезапуска клиента. [SDK/stdio](../BENCHMARK.md#configuration-only-connection-continuity)

<a id="resource-examples"></a>
**Когда использовать или отказаться:** Для нескольких сессий с одним коннектором и каталогом. Для одной сессии или лёгких бэкендов прямой MCP может быть проще. В лёгком тесте сумма рабочих наборов процессов выросла с 357.0 → 564.0 MiB; первый общий запрос от запуска нового шлюза до полезного результата занял 1886.7 ms против 503.5 ms напрямую. Чистый выигрыш зависит от накладных расходов. [BENCHMARK](../BENCHMARK.md#sharing-model-and-evidence)

<a id="first-use"></a>
## Первый полезный результат: разрешённое чтение через шлюз

Нужны Node.js 24+, npm, Git, Copilot CLI с плагинами и уже настроенные MCP-интеграции с необходимой аутентификацией. Первичная установка идёт через Copilot CLI; Windows — основная проверенная платформа. Глубина проверки клиентов различается. [Copilot `/help` · `/plugin`](../CLIENTS.md#copilot-plugin-eligibility).

**До установки:** Конфигурация, приватный каталог и резервные копии могут содержать учётные данные: не публикуйте их. Бэкенды могут обращаться к удалённым сервисам. Устанавливается постоянная среда выполнения; восстановление настроек или удаление плагина не останавливает шлюз. [REFERENCE](../REFERENCE.md#planned-exit) Локальное приватное состояние и сохранённые токены шлюза доступны только владельцу и дополнительно не шифруются.

```powershell
copilot plugin marketplace add yeelam-gordon/MCPGateway
copilot plugin install shared-mcp-gateway@mcp-gateway
```

1. Откройте Copilot CLI и вызовите `/mcp-gateway-setup`. Проверьте предварительный просмотр и подтвердите только нужные изменения. Сохраните приватные копии и команды отката. Сам плагин не объединяет конфигурации.
2. Закройте и снова откройте Copilot; выполните точный возвращённый `readinessCommand` по инструкции для объекта команды. Проверка не запускает отсутствующий шлюз. [readinessCommand](../REFERENCE.md#readiness-command-object) Сохраните только возвращённый JSON-объект: `.command` — одобренный исполняемый файл, `.args` — точные аргументы в исходном порядке.
3. Выберите безвредное разрешённое чтение в существующей интеграции. Замените только задачу в скобках; псевдонимы, инструменты и аргументы берите из обнаружения и схемы, не придумывайте.

> Используй шлюз для [моего разрешённого чтения]. Выполни `list_servers`, целевой поиск через `search_tools` и `get_tool_schema`; подготовь аргументы по схеме с разрешёнными несекретными тестовыми значениями. Получи обычные согласования. При `requiresExclusiveAccess: true` один раз вызови `claim_server` до `call_tool`, затем `release_server` после всех вызовов; без требования монопольного доступа захват не нужен. Покажи реальную запись или документированный пустой результат и проверь ошибки, а не только ответ шлюза. При неизвестном исходе не повторяй вызов: оставь блокировку и передай случай владельцу установки приватно.

4. Во второй сессии с тем же коннектором и каталогом найди тот же псевдоним: ожидаются `ready` и те же возможности. Это проверка общего обнаружения, не идентичности процесса или экономии RAM. [MCP](../REFERENCE.md#first-shared-workflow) [Публичный пример echo и результата](../REFERENCE.md#public-echo-illustration).

**При сбое:** Для пустого каталога проверьте конфигурацию и предварительный просмотр; ищите слова из описания бэкенда. Аутентификацию и готовность проверяйте по справочнику, без обходного процесса. Освобождение доступа или отключение не отменяет и не снимает безопасно блокировку неизвестного монопольного вызова. Сверьте исход, согласуйте перезапуск собственного шлюза и захватите доступ заново. [Authentication](../REFERENCE.md#native-http-oauth) · [Recovery](../REFERENCE.md#setup-recovery) · [Unknown outcome](../REFERENCE.md#unknown-exclusive-result)

**Завершение использования:** Завершите работу и вызовы, восстановите или удалите коннекторы затронутых клиентов, затем по процедуре передачи оператору проверьте остановку собственного шлюза. Откат конфигурации — не остановка процесса. Сохраните приватное состояние, учётные данные, историю и посторонние процессы. [Exit](../REFERENCE.md#planned-exit)
